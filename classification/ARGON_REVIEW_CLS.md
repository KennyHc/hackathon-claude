### 2. Binary `P(ITEM)` Design & 1.5h Priorities
* **Right call:** With 99.98%+ no-item category accuracy, a 22-class GBM wastes 22x compute on what linear tokens + [`RULES`](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/categories.py#L335-L349) + [`reversal_pairs`](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/categories.py#L225-L245) already solve. Both active levers in [`integration/run.py`](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/integration/run.py#L39-L62) (`p_items < 0.2` veto and `p_items < 0.97` `UNIDENTIFIED` gate) are driven by `p_items`.
* **Priorities for 1.5h:**
  1. **Drop `xgb`** (redundant with `lgb` on identical features) to save ~35% compute; keep **`lr` + `lgb` + `chr`**.
  2. **Stage cutoffs:** Run `val` (`2024-07-01`, `2025-01-01`) first; only fit `hold` (`2023-07-01`, `2024-01-01`) and `final` (`9999-12-31`) for the winning candidate.
  3. **Fix `compose()` float32 bug and stacker calibration at `0.97`** before evaluating (below).

### 3. Bugs in `zoo.py` / `zoo_run.py` / `eval_cls.py`
* **`float32` catastrophic cancellation in [`compose()`](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/zoo.py#L330-L337):** [`lr_proba`](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/zoo.py#L253-L258) runs in `float32` (`coef` is `float32`). When `P_lr[:, ji]` rounds to `1.0` in `float32` (happens whenever $\sum_{c \neq \text{ITEM}} P_c < 6\times 10^{-8}$), `rest = np.clip(1 - P_lr[:, ji], 1e-12, None)` becomes `1e-12` while individual `P_lr[i, c]` can be $\sim 5\times 10^{-8}$. Multiplying by `(1 - p_items) / 1e-12` explodes `P[i, c]` and `confidence` to **$> 1.0$ (up to $50,000\times$)**, corrupting `argmax` ties and falsely triggering the `confidence >= 0.9` veto. *Fix:* cast to `float64` in `lr_proba` and compute `rest = P_noitem.sum(axis=1)`.
* **Redundant 4x recomputation in [`zoo_run.py`](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/zoo_run.py#L77-L83):** Calling [`fit_stacker(cutoff, [m], tc)`](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/zoo.py#L300-L322) per member and then for `members` recomputes `_hist_tables`, `dense()` (`merge_asof` on 200k rows), and `lr_proba` **4 times** on the same slice. Call `fit_stacker(cutoff, members, tc)` once and reuse its `st["slice_probs"]`.
* **Calibration shift vs fixed `UNID_P = 0.97` ([zoo.py](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/zoo.py#L315-L316), [integration/run.py](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/integration/run.py#L27)):** `UNID_P = 0.97` was tuned to overconfident `C=4` LR probabilities. Platt/stacker calibration pulls upper-tail probabilities down toward true empirical rates, shifting the effective threshold and inflating `UNIDENTIFIED` false positives if `0.97` is held fixed.
* **Missing file crash in [`eval_cls.py`](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/eval_cls.py#L77-L87):** If `classification/out/<phase>/line_labels.parquet` (`dst`) does not exist yet (e.g. fresh `hold`), `shutil.copyfile(dst, bak)` and `shutil.move(bak, dst)` in `finally` both raise `FileNotFoundError`.
* **Wiring gap ([classification/run.py](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/run.py#L43-L44)):** `categories.label` does not call `zoo.py` yet, and [`zoo_run.py`](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/zoo_run.py#L61-L65) requires loading the full 1.49M-row `train_cache()` just to get `tc["vocab"]` and `_hist_tables`.

### 4. Cheap, Leakage-Safe Fix for the Decision Population
* **Fit the stacker on the decision-proxy slice in `[c0, end)` ([zoo.py](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/zoo.py#L309-L316)):** Restrict (or heavily upweight) the stacker training rows in `[c0, end)` to **receipts (`amount > 0`) whose `< c0` LR best no-item class is `UNIDENTIFIED`**, and add `P_lr(UNIDENTIFIED | ~ITEM)` to `Z`.
* **Quantile-match to `P_lr(ITEM)` on that slice:** Monotonically map the stacker's `p_items` on that slice to match the quantiles of `P_lr(ITEM)` (especially at the `0.97` quantile) so `UNID_P = 0.97` stays at the exact same operating point while using the ensemble's superior ranking. Costs <1s and zero leakage.

### 5. Risks for FINAL (`ZA01` / `ZAR`, Runtime, Fallback)
* **Currency-blind tree splits on `ZAR` ([zoo.py](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/zoo.py#L122-L135)):** `dense()` feeds raw `log10(|amount| + 1)` and `a % 100 == 0` without FX normalization (1 EUR $\approx$ 20 ZAR), and every `ZA01` counterparty has `n = 0` history. Trees (`lgb`/`xgb`) splitting on `amount x (n == 0)` will miscalibrate on `ZA01`. *Fix:* divide `a` by currency median (or `orig_amount` ratio) in `dense()`, or blend conservatively with `lr` when `n == 0`.
* **Inference-time `train_cache()` load ([zoo.py](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/zoo.py#L292-L294)):** [`member_probs`](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/zoo.py#L286-L297) loads the entire 1.49M-row `train_feats_v1.pkl` and rebuilds `_hist_tables` at test time. Pre-save the static `< 2025-07-01` final `(n, item, unid)` counts per key so `FINAL` never touches `train_cache()`.
* **Two-tier fallback ([categories.py](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/categories.py#L353-L387), [classification/run.py](file:///Users/luigizheng/Desktop/Close_the_tabs-cls/classification/run.py#L45-L48)):** Compute `P_lr` first in `categories.label`, then wrap the `zoo` ensemble in `try/except` falling back to `P_lr` (not to `run.py`'s dummy `baseline()`, which tanks the score).
