### 1. Party Resolver & Subset-Sum Risks
- **Unscoped alias keys (`party.py`)**: `customers.csv` (55.7k IDs, 37.0k unique names) and `suppliers.csv` share names across entities. Keying aliases globally without scoping to `(entity, direction)` (expanding `ES00 → {ES00, ES01, ES02, PT01}` for AP) will drop purity below `0.9` on shared names and cause cross-entity false matches.
- **"Longest key wins" + fixed prefixes (8–40 chars)**: In [PLAN.md](file:///Users/luigizheng/Desktop/Close_the_tabs/matching/party/PLAN.md#L25-L32), taking 8–40 char prefixes after stripping bank prefixes includes trailing remittance noise (`... INVOICE INV21-`, `... SUPPLIES`). A 40-char noisy prefix with 1 train hit (`1/1 = 1.0` purity) will beat a 20-char true name prefix, while 8-char prefixes (`PISCINAS`, `SERVICES`) collide. Require `count >= 3` for short/noisy prefixes, strip trailing concept words (`INVOICE`, `FATURA`, `SUPPLIES`, `PAYMENT`, `SERVICE...`), and index `items["party_name"]` from [`load_items`](file:///Users/luigizheng/Desktop/Close_the_tabs/integration/lib/ledger.py#L75-L194) to catch pre-rename names on open invoices and `FINAL` (`ZA01`) parties.
- **Mid-string third-party markers**: Prefix-stripping misses `ORD. <customer>` (`ar_third_party_confirming`), `EXPTE <n> <customer>` (`ar_third_party_agency`), and `/ORDP/<party>/`. Extract regex captures for these before prefix slicing.
- **Step 2e (`ar_partial`) firing before group/parent fallback**: In [PLAN.md](file:///Users/luigizheng/Desktop/Close_the_tabs/matching/party/PLAN.md#L31-L44), if a parent/holding has 1 open item > cash, Step 2e will falsely claim it as `PARTIAL` instead of falling back to `group_id`/`parent_customer_id` children (or leaving `unidentified_lookalike` unclaimed). Run group fallback for exact/shortfall matches (2a–2d) *before* 2e, and require a text cue (`PAYMENT`, `A CUENTA`, truncated ref) for 2e.
- **Subset-sum blow-up & contradiction (2c)**: `50 ms × 10k` unresolved lines = 500s (breaches 10-min limit). Since `ar_ref_noise` has no credit notes ([PLAN.md](file:///Users/luigizheng/Desktop/Close_the_tabs/matching/party/PLAN.md#L10)), run positive-only branch-and-bound first (filter `open_amount <= cash + tol`, prune when partial sum > target, cap at ~5 ms / 2,000 nodes), and only include `ARC`/`APC` if that fails. Also fix the contradiction in [PLAN.md](file:///Users/luigizheng/Desktop/Close_the_tabs/matching/party/PLAN.md#L38-L39) (*"prefer oldest set"* vs *"two minimal solutions → skip"*): equal-amount items always have multiple minimal sets—break ties by oldest `issue_date` (FIFO per [POLICIES.md](file:///Users/luigizheng/Desktop/Close_the_tabs/docs/POLICIES.md#L96)).

### 2. Cut / Reorder for Points/Hour (80-Min Budget)
- **Promote `OVERPAYMENT` & `DUPLICATE_PAYMENT` from Task 5 to Task 2 (+4.0 pts)**: Each of the 10 exception classes is worth **2.0 full points** (`0.2 * 100 / 10`). [`assign_exceptions`](file:///Users/luigizheng/Desktop/Close_the_tabs/classification/exceptions.py#L83-L155) cannot emit `OVERPAYMENT` or `DUPLICATE_PAYMENT` unless a matcher claims the line. Both are 10-line checks on single-item matching.
- **Merge Task 4 (`ap_paid_by_holding` + `FRAS` parser) into Task 1/2 (+2.8 pts)**: Allowing `ES00` AP lines to search `ES01/ES02/PT01` supplier items + regexing `FRAS (\d+)` takes ~15 lines of code for 7,334 val lines.
- **Cut `ar_discount_late` (788 lines, 0.3 pts) from v1**: Averaging 3.7 items/line with mixed on-time/late items, it has low ROI and risks corrupting `SHORT_DISCOUNT` (6,317 lines).
- **Allow cross-currency in 2a**: [EDA.md](file:///Users/luigizheng/Desktop/Close_the_tabs/docs/EDA.md#L268-L273) shows `FX_DIFFERENCE` is the top exception on `ar_same_amount_fifo` and `ar_same_amount_month`; don't hard-filter `item.currency == line.currency` when `orig_amount`/`orig_currency` (or FX conversion within spread) matches.

### 3. Concrete Amount & Exception Pitfalls
- **`OVERPAYMENT` amount ([PLAN.md](file:///Users/luigizheng/Desktop/Close_the_tabs/matching/party/PLAN.md#L44))**: Must output `amount = open_amount`, **never** `cash` ([POLICIES.md §2](file:///Users/luigizheng/Desktop/Close_the_tabs/docs/POLICIES.md#L32)). If you output `cash`, [`assign_exceptions`](file:///Users/luigizheng/Desktop/Close_the_tabs/classification/exceptions.py#L295) sees `cash == amount` and drops the `OVERPAYMENT` label.
- **`PARTIAL` is NOT passthrough in [`assign_exceptions`](file:///Users/luigizheng/Desktop/Close_the_tabs/classification/exceptions.py#L34)**: Only `RETURNED`, `DUPLICATE_PAYMENT`, `SHORT_DISPUTE`, `UNIDENTIFIED` pass through; `PARTIAL` is recomputed from `open_after > tol` ([`exceptions.py`](file:///Users/luigizheng/Desktop/Close_the_tabs/classification/exceptions.py#L276-L287)). In `ap_partial` (4.9 items/line) and `ar_discount_late` (3.7 items/line), fully paid items must get `amount = open_amount` (`""`), and **only** the short item gets `amount = remaining_cash` (`< open_amount`).
- **Discount & withholding base ([PLAN.md](file:///Users/luigizheng/Desktop/Close_the_tabs/matching/party/PLAN.md#L11-L17))**: Both are computed on item `total_amount` (rounded per item: `Σ round(total_i * pct, 2)`), **not** `open_amount`, while row `amount` must be `open_amount` ([`exceptions.py`](file:///Users/luigizheng/Desktop/Close_the_tabs/classification/exceptions.py#L335-L370)). Fall back to `customers.csv` for `payment_terms` when blank on `open_items_at_start`.
- **`ar_same_amount_month` Dec rollover**: `month + 1` for `"DECEMBER"` / `"DICIEMBRE"` must roll to `(year + 1, 1)` across EN/ES/FR/DE/IT/PT month names.
- **`DUPLICATE_PAYMENT` closed items**: [`load_items(phase)`](file:///Users/luigizheng/Desktop/Close_the_tabs/integration/lib/ledger.py#L75-L194) only loads `open_items_at_start` + in-phase invoices; items settled *before* phase start aren't in `items` unless looked up from prior-phase invoices. Also cover AP (`ap_duplicate_payment`, 66 val lines).
